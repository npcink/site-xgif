## 这轮保留下来的做法

- **组图发现和跟进分开做。** #111 记录了两种漏项：洛必达两图在首轮都未公开，逐图查询已发布图库的 M4 Ollama 向量流程没有让两图互比；后来是操作端 macOS Vision OCR 提供共同关键词，再以原图并排确认。游戏角色先进入候选，但搁置后没有及时回看。批内补目录／主题并排复核，记录搁置理由与复核条件；本机 OCR 查字、M4 视觉向量看片，不凭相似度自动合组，不把批次权限当作署名或出处证据。
- **内容确认与展示实现分开。** 确认成员、顺序、封面不等于确认新增独立合集页。连续浏览优先复用可左右滑动的图集；第 9 节[开发与交付规范](DEVELOPMENT_AND_DELIVERY_STANDARD.md#9-产品与界面规范)记录了桌面缩略图的实际位置、窄屏翻页、原尺寸上限、节制的标签和操作。整合 #111 时同步修订其「优先用合集页」措辞，保留稳定 ID、原图和回退约束；不扩大旧链接移除范围。
- **小改动先验真样本。** 先用截图的页面、组件和内容 ID 复现，明确会受影响的复用位置；按单图、动图、两图与长图集检查，不把图集当静态单图。先看未遮罩的桌面与窄屏，再跑受影响的 Linux 视觉用例，勿用全量重跑代替定位。按最终组合核对生产 CSP，而不是仅看预览或链接是否返回 200。
- **候选数和展示数分开。** 缺一张先检查已看过滤、候选窗口和实际容器宽度，再查图片加载。只改候选上限且模型摘要与原始依据指纹相符时，复用向量缓存；缺合格候选不靠放宽相似度凑数。操作入口见[内容工具手册](../../workflow/README.md)。

## 继续交付与清理的顺序

1. 原本地主目录落后公开主线，含未提交工作与私有资料，不直接拉取、重置或清理。继续开发从验证过的 `origin/main` 建立隔离工作区；恢复点区分公开代码和各工作区的私有状态。
2. 进入主线且逐份核对文档后，将 #111 标记为被 #113 替代，不把独立工作区的组图复核命令混入。发布阶段结束不等于所有历史工作区都能删除；逐一核对归属、未提交状态、ignored 资料和进程占用。
3. 只提交核验后的公开代码、清单、测试和文档。整合后跑站点、工作流、发布快照以及相关 Linux 视觉、生产 CSP 回归；必要检查与待合并的准确 head 一一对应。
4. 获得此次生产发布授权后才能合并触发部署。核验线上 SHA 和关键页面，最后逐个核对私有备份、PR、分支及 worktree 后再清理。按[仓库收尾与 Git 卫生规范](REPOSITORY_CLOSEOUT_AND_GIT_HYGIENE_STANDARD.md)区分「可以结束会话」和「生产已收尾」。
