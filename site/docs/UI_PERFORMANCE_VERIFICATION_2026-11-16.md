# 界面与图片性能验证（2026-11-16）

## 修复范围

1. 原图与展示图分离：卡片、详情和缩略图生成静态 WebP，图集其他大图切换时加载；主动查看／保存仍访问原文件。动画保留帧、时长、循环。无需 Cloudflare 付费转换服务。
2. 首页第一张图片改为优先加载；图片按完整比例展示，标题、说明、标签和数量放在图下，图片列表采用最短列瀑布流。
3. 搜索先完成初始筛选再显示结果；字体改为可选加载，保留无 JavaScript 和脚本失败回退。
4. 缩短列表头部，避免手机长标题留下单字尾行；补输入焦点、深色强调文字与按钮状态对比度、合理标题层级、44px 主要点击区域、320px 页脚换行、最多 5 个页码、平板详情折叠侧栏。

公开 Markdown、原文、原图 URL、原图字节、稳定 ID、公开状态和推荐清单均未修改。实现与取舍见 [ADR-028](decisions/ADR-028-static-webp-display-images.md)。

## 本地实验数据

使用 Chrome、Lighthouse 13.6.0 默认移动端模拟，固定构建完成的静态产物，完整网络请求样本。测试环境与真实用户网络不同，数字是实验结果，不是线上用户 Core Web Vitals。原审计中未完成请求的图集样本不作对照。

| 页面 | 原问题／完整旧样本 | 修复后样本 |
| --- | --- | --- |
| 首页 | 首图 lazy，LCP 约 6.5–6.8 秒 | 性能 99，LCP 约 2.0 秒，CLS 0，传输约 313 KiB |
| 搜索 `?q=AI` | 初次隐藏大批结果，CLS 约 0.314 | 性能 93，LCP 约 2.9 秒，CLS 0，传输约 729 KiB |
| 8 张插画图集 | 完整样本首屏约 9.25 MiB | 性能 98，LCP 约 2.4 秒，CLS 0，首屏约 568 KiB，减少约 94% |

这三项修复后样本的可访问性均为 100，无浏览器控制台错误、无未完成请求。搜索页有意 `noindex`，SEO 69 属于产品策略，不通过移除 `noindex` 制造满分。压缩图的文案、细节可在原图核对；WebP 不是保证体积更小的魔法格式，尺寸与加载范围才是收益来源。

## 回归范围

构建与内容契约、站内链接、真实 WebP 格式／缩略图宽度、有限循环动画、Linux 桌面和移动视觉、搜索启动 CLS、320px 宽度、焦点、分页、768px 正文、无 JavaScript、图集按需加载与原图链接、键盘／触控／弹窗、CSP 下瀑布流均纳入验证。验证记录只在对应命令成功后作为通过依据；合并与实际部署另核对。

## 保留问题

- 爱站原脚本仍使用 `new Function` 与 `unload`，当前 CSP 会阻止相关动态执行，也会影响 bfcache。没有找到可核验的兼容开关；保留用户指定服务，不加入 `unsafe-eval`，需服务商兼容版或另行更换服务。
- 列表和搜索仍使用完整静态索引，DOM 数量可继续优化，但本轮没有主线程长任务证据，不扩大为服务端搜索或新 CMS。
- 冷构建依赖公开 R2 和动画编码，网络失败时保持构建失败并重试，不静默退回原图或宣称已部署。构建、浏览器测试与性能采样依次执行，避免重写同一份 `dist` 导致假 404。
- 文章页外部非受管封面、SVG 和缺少尺寸的图片保持直出；未来新增源需单独核验，不能自动扩大远端域名白名单。
