状态：生效

版本：1.2

日期：2026-08-03

补充：2026-11-02（连续浏览、离线推荐、图片查重与收尾复盘）

适用范围：`site-xgif` 的站点、内容、按需内容工具、GitHub 与 Cloudflare 交付流程

## 1. 目的

本规范把项目从 2026 年 7 月至 8 月的开发、排错、发布和复盘经验固化为后续人和 AI 都必须遵守的工作方式。目标不是让流程更复杂，而是保证单人项目始终具备以下特征：

- 能用最少系统完成真实内容发布；
- 内容、状态和发布结论有可核对的事实来源；
- 任何失败都尽量可恢复，不覆盖用户工作；
- 只为重复发生的真实问题增加复杂度；
- 每个改动足够小，能够独立审查、验证和回退。

历史事实、PR、测试结果和本轮纠错过程见[下一阶段实施收口](NEXT_STAGE_IMPLEMENTATION_CLOSEOUT_2026-08-03.md)。架构取舍见 [ADR-017](decisions/ADR-017-retain-astro-over-hexo-or-ghost.md) 和 [ADR-018](decisions/ADR-018-retain-local-publisher-and-learn-from-open-source-cms.md)。阶段完成后的分支、worktree、私有运行状态和假差异处理见[仓库收尾与 Git 卫生规范](REPOSITORY_CLOSEOUT_AND_GIT_HYGIENE_STANDARD.md)。

## 2. 项目基本判断

XGIF 当前是一个由单人使用 AI 开发和维护的轻内容站，不是多人 SaaS、通用 CMS 或内容平台。默认技术方案保持为：

- Astro 静态站点；
- Markdown 公开内容；
- AI 直接管理 Markdown 与按需内容工具；
- 可重建的本地 SQLite 索引；
- GitHub PR 作为公开变更入口；
- Cloudflare Workers Builds 作为正常生产部署路径。

在真实需求没有改变以前，不切换 Hexo、Ghost 或数据库型远程 CMS，不新增多租户、账号权限、在线协作、消息队列、第二套内容数据库或常驻后台服务。

## 3. 决策原则

### 3.1 真实问题优先

进入开发的事项至少满足一项：

1. 同一个问题在两次或以上真实操作中重复出现；
2. 问题可能造成内容错误、来源失真、覆盖较新版本或无法恢复；
3. 问题阻断“创建或导入 → 复核 → 本地发布 → 同步 PR → 合并 → 线上核验”；
4. 一个小改动能够稳定消除每次都会发生的重复操作。

未达到门槛的想法只进入待观察清单，不立即实现。不得以“其他 CMS 有”“以后也许需要”或“AI 可以顺便做”为理由扩张范围。

### 3.2 先处理主要矛盾

每一阶段只确定一个主攻目标。优先级顺序为：

1. 数据正确性与可恢复性；
2. 发布事实与状态可信度；
3. 能否完成真实工作流；
4. 高频操作效率；
5. 视觉和低频便利性。

安全事实链未闭合时，不先做视觉重构；真实操作尚未重复时，不先建通用能力。

### 3.3 吸收经验，不复制系统

借鉴开源 CMS 时只吸收可独立验证的模式，例如草稿与发布分离、版本记录、显式复核、可恢复删除、清晰的主动作和诚实状态。不得因为借鉴 Ghost、WordPress 或其他项目而复制其账号体系、插件体系、多人审批或线上运行时。

## 4. 不可破坏的架构边界

| 边界 | 规范 |
| --- | --- |
| `site/` | 只负责公开 Astro 站点、已上线内容、可在仓库公开阅读的草稿、站点测试和部署配置。 |
| `workflow/` | 只在本机运行，负责确定性检查、图片操作、恢复和 Git 内容同步，不运行管理服务；不得部署到公网。 |
| `old/` | 只读历史视觉参考，不参与构建和发布。 |
| Markdown | 公开内容权威源；标题或日期可改，`contentId` 不可重建。 |
| SQLite | 派生索引，必须能够从 Markdown 和旁车数据重建，不能成为唯一内容真相。 |
| R2 / 本地图片 | 图片字节来源；公开内容必须保存可核对的来源、授权或待核实声明。 |
| GitHub | 公开程序、允许在仓库公开阅读的内容、PR 和部署历史；私密草稿、私有正文、凭据与运行日志不得进入公开提交。草稿入库不等于生产展示，见 [ADR-031](decisions/ADR-031-repository-drafts-and-production-visibility.md)。 |
| Cloudflare | 只部署 `site/` 的静态产物；正常发布等待 Workers Builds，不能与手工 Wrangler 并行部署同一提交。 |

改变以上任一边界前必须：提供真实不足证据、比较最小替代方案、写新的 ADR，并说明迁移与回退方式。

## 5. AI 使用边界

AI 可以：

- 生成可编辑的标题、摘要和标签候选；
- 在不改变原文字节顺序的前提下增加 Markdown 段落空行；
- 帮助检查代码、测试、文档和工作流；
- 根据明确事实给出建议和批量处理方案。

AI 不可以：

- 自动确认来源、作者、授权或内部人工复核；
- 改写、删减、截断或合并导入正文后宣称只是“排版”；
- 让发布助手或无人值守 AI 自动化自行合并公开内容 PR；只有得到明确授权且必需检查通过后才可合并；
- 把推送、HTTP 200、CI 绿色或候选构建说成“已上线”；
- 在证据不足时猜测线上状态、运行版本或用户验收结论。

任何 AI 生成结果都必须保持可编辑、可拒绝，并在写入或发布前通过确定性校验。

## 6. 变更切分规范

每批改动在编码前写清楚：

- 要解决的一个具体问题；
- 验收条件；
- 明确不包含的内容；
- 受影响的路径和事实边界；
- 最小验证方法。

一批改动应能单独提交、单独测试、单独 PR、单独回退。禁止把内容迁移、发布状态、编辑器重构、首页视觉和基础设施改造混在一个大提交里。

当旧分支包含大量混合改动时，以最新 `origin/main` 为基线重建最小垂直切片，不整批复制旧差异。

## 7. Git 与 worktree 规范

### 7.1 开工前

必须核对：

```bash
pwd
git status -sb
git branch --show-current
git fetch origin main
git rev-parse origin/main
git worktree list
```

共享目录存在未提交修改时，默认这些修改属于用户或其他任务。不得 reset、stash、checkout 覆盖、批量格式化或顺手提交。

### 7.2 隔离开发

- 从最新 `origin/main` 创建 `codex/*` 独立分支和 worktree；
- 在该 worktree 内单独安装依赖和执行测试；
- 提交前再次核对绝对路径、分支和 `git status`；
- 只 `git add` 明确列出的文件；不得使用会把运行记录一起带入的宽泛暂存；
- 普通代码或文档 PR 不得顺带提交 `workflow/records/*.jsonl`；
- `flomo-imports.jsonl`、`r2-assets.jsonl` 和 `user-provided-assets.jsonl` 是受 Git 跟踪的隐私最小化内容台账，只能在对应内容发布批次中精确暂存；
- `publication-events.jsonl`、`.env`、SQLite、私有来源、原始导入包和本地备份不得进入公开提交。

### 7.3 推送与合并

`main` 受保护，正常流程为：

```text
独立分支 → 精确提交 → push → PR → 必需检查 → 合并 main
```

普通 Git 操作用 `git`；只有 PR、checks 和 GitHub API 使用 `gh`。多 worktree 环境下，远端合并后必须用 `gh pr view` 或 API 核对状态和合并提交，不得仅凭本地切换分支是否成功判断合并结果。

### 7.4 阶段收尾

- `git status` 只用于发现候选，不能证明文件是否尚未进入主线；旧分支收尾应逐文件比较工作区与 `main:<path>` 的 blob；
- squash、cherry-pick 或重建合并的分支不能只依赖 `git branch --merged` 判断，应结合 PR、树内容、开放 worktree 和替代实现；
- 不为了得到空白状态制造提交；旧实现、旧视觉基线和私有运行数据应分别舍弃、保留或进入私有历史；
- 删除主 worktree 或原地切换前，先盘点 `.env`、SQLite/WAL、备份、私有来源、回收站和导入包，并停止占用进程；
- 详细流程、删除矩阵和最终核对清单以[仓库收尾与 Git 卫生规范](REPOSITORY_CLOSEOUT_AND_GIT_HYGIENE_STANDARD.md)为准。

## 8. 内容与发布事实规范

### 8.1 内容状态

面向编辑者的主状态保持互斥：

1. 草稿；
2. 发布中；
3. 已核验上线。

“发布中”可以用次级筛选区分本地待同步、PR 待合并/部署和待线上核验。内容体检问题不与发布进度混为同一个主状态。

### 8.2 事实层级

报告时必须区分：

| 层级 | 能证明什么 |
| --- | --- |
| 本地测试通过 | 当前 worktree 的代码通过所执行的测试。 |
| 提交并 push | 远端分支存在该候选。 |
| PR checks 通过 | 候选满足配置的 CI / 构建门槛。 |
| 合并 main | 源码已进入受保护主分支。 |
| Cloudflare 构建通过 | 指定提交完成部署构建。 |
| `/build.json` 与线上探测一致 | 线上运行的是指定提交且所探测路径正常。 |
| 人工验收 | 真实任务和展示满足使用者预期。 |

后一层不能由前一层推断。任何报告必须说明证据停在哪一层。

### 8.3 内容同步

- 内容同步只能创建或复用合法的开放 `content-sync/*` PR；
- 自动化永不自动合并；
- 失败必须保留已推送分支、错误事实和手工比较入口；
- 本地删除不等于线上删除，必须经过版本化 `git rm`、推送、合并和线上消失核验；
- 发布、删除和恢复都必须携带内容版本或哈希，拒绝覆盖较新的 Markdown。

## 9. 产品与界面规范

独立文章页使用全站导航的「文章」入口，页眉不重复放返回列表链接。元信息、标题、摘要和正文之间用紧凑间距分隔，不另加正文前横线；摘要字号小于正文，正文栏居中、段落左对齐，带目录的文章保留侧栏。有冒号的标题优先在冒号后换行，不改标题字符或原文首段。文章弹窗保留关闭与打开独立页入口。桌面和手机向下阅读时，独立页与弹窗分别基于自身滚动距离显示「返回顶部」，不滚动或聚焦背景页面。

图片编组确认只涵盖成员、顺序与封面，不等于同意新增页面。需要同组连续浏览时，默认复用图片详情的图集组件，保留已发布图片的 ID、原图和旧入口；旧入口仅在用户明确同意后移除（小吃摊图集为已确认的例外）。验收时从图片库实际打开图集，在桌面和移动端操作换图与保存入口；生产构建还须在同款 CSP 下检查计算样式和布局。链接返回成功不能代替实际浏览验收。

已归入图集的成员不再重复占用公开推荐和检索入口；成员名称仍应能搜到图集。图集卡片显式标注类型和张数，原始素材与成员 ID 保留。

所有多图图集共用一条缩略图栏，不按内容 ID 启用特殊布局。宽屏取消主图下整条翻页栏，缩略图放在右栏来源信息下方；三张及以下只在缩略图旁显示页码，长图集在同处保留紧凑箭头。窄屏保留主图下的翻页按钮和页码，随后是缩略图栏，同时支持左右滑动。两图与小吃摊三图都要在独立详情页和弹窗核对实际位置：短图集横纵均不溢出，长图集只横向滚动；换图保持主图区域尺寸，查看原图跟随当前帧，收藏和复制仍以图集为单位。

图片详情页和弹窗共用同一信息栏：媒体类型 → 查看原图或放大版 → 收藏和复制 → 分类、标签及非空情绪／场景 → 来源。宽度不足时两项次要操作一起换行，不压缩点击区域。单图和动图不增加缩略图或大标题；放大版标记、所属合集、来源和权利入口仍按原数据展示。

图片详情按公开素材的实际尺寸设上限：空间不足时等比缩小，不放大填满版面。单图画框随图片收紧；图集切换时保持展示区域和翻页控件位置不变，逐张按各自尺寸居中。尺寸来自同源的构建期样式，不能以 `srcset` 的密度换算宽度替代素材像素尺寸，也不修改图片文件。

详情页下方的「接着看图片」使用独立的紧凑网格，不复用图片库的满宽展示。标题与「更多图片」和下方文章推荐对齐。按实际容器宽度排四列（至少 880px）、三列（520–879px）或两列（不足 520px），最多两行未看过的候选；候选不足不凑数。缩略图在等高画框中居中，保持原比例且不超过素材尺寸；动图仍以静态首帧预览。验收应滚动到推荐区，分别检查独立页和弹窗中未遮罩的实际卡片，而不只对比主图区。

图片库和相关推荐中，图片本身就是入口，不重复展示常驻边框、话题标签和跳转箭头；普通静态图不留空底栏。图集保留类型和张数，动图保留媒体标识，键盘焦点仍须可见。移除卡片上的话题标签只改变展示，不删除内容元数据，也不影响按标签筛选和详情页的标签入口。

- 保持 PC 优先、简单、直接、高效；
- 一个任务只保留一个明确主动作；
- 高频动作直接可见，低频设置进入侧栏、详情或“更多”；
- 状态名称描述事实，不描述内部实现步骤；
- 批量工作应集中一次人工复核，允许少数例外逐条覆盖；
- 不因功能存在就增加按钮，先证明它减少真实操作成本；
- UI 改动必须验证真实交互路径、键盘/可访问性和控制台/网络结果；静态断言不能替代浏览器证据；
- 只有布局或视觉合同确实改变时才更新截图基线，不能用批量更新掩盖回归。

### 界面排查清单

1. **页面 × 状态 × 宽度。** 先列出改动模板及复用位置，涵盖首屏和页尾；按实际功能选默认、加载、失败与重试、空结果、有结果、清空、分页、弹窗和前进后退。检查窄屏与关键断点两侧，不只测一个桌面和一个手机尺寸。
2. **看全貌，也量内部。** 用未遮罩截图检查首屏、页尾、阅读顺序、留白和重复文案。再量图片内容区的中心与边界、标题到操作区的距离、图标的可见尺寸及点击区，区分正常换行与容器占宽错误。图片选横图、竖图、方图、动图和长图集；确认真实图片已载入。
3. **按用途去重。** 在当前任务和当前屏幕内对照链接、按钮、计数和标签。合并同一位置的重复入口；保留有独立用途的返回、空态下一步、分组跳转和图集跳选。状态不可用时，撤下无效控件并保留能工作的入口。
4. **按真实路径复测。** 用键盘和触屏路径检查焦点顺序、退出弹窗后焦点恢复、移动菜单和返回顶部。模拟慢请求、失败、存储受限及无脚本，核对控件和真实落点。只为复现过或容易回退的行为补回归断言。
5. **分开记录证据。** 说明检查过的状态、宽度、未覆盖项、截图和复现步骤。本机交互与未遮罩截图不能替代 Linux 正式视觉基线；执行器未启动时明确记录原因和待验范围。
6. **按操作定义失败后的保留状态。** 新筛选可以先保存用户输入以便刷新重试，但请求失败时不把旧卡片和计数当成新结果；普通翻页等新内容到位后再更新页码与历史。分页直链失败时，区分 URL 请求页码和实际展示的回退页码。用暂停请求覆盖交叉操作：筛选未完成时尝试旧分页，分页失败后用键盘重试，同时断言地址、卡片、页码和焦点，不只检查错误文案。
7. **用确定性条件覆盖历史与路由边界。** 偶发错误先和相同环境的未改主线对照，再用延迟资源等方式固定事件顺序。核对地址、实际文档与展示方式，不以 URL 匹配代替内容匹配。404 用部署运行时请求不存在的地址，同时核对 HTTP 状态、导航和是否意外重复加载。

## 10. 验证规范

验证范围按风险选择，但不得低于改动所触及的事实层。

### 10.1 内容工具改动

通常需要：

```bash
cd workflow
npm test
```

涉及恢复或 R2 时，再运行对应备份、恢复演练或对账命令。工具测试使用隔离目录，不依赖真实草稿数量或操作生产资源。

### 10.2 站点改动

通常需要：

```bash
cd site
npm test
```

涉及交互时增加针对性的 Playwright 用例；涉及布局时运行 Linux 视觉基线；涉及部署配置时运行 `npm run check:deploy`。

#### 小范围界面调整

2026-11-25 图片卡片复盘：去边框本是局部调整，但反复增删标签、误动相关推荐的动图标识，又把图集当成静态单图，导致重复构建和验证。耗时的主要原因是范围和样本没先核准，不是 Linux 验证本身。

1. **先定范围。** 对照截图确认具体页面、卡片和元素，查清组件复用位置。只改确认过的展示规则，不顺手改数据、标识、交互或其他版式。
2. **先验原样本。** 用截图中的内容 ID 或目录中的实际数据定位，不假定样本在第一页。先在本地桌面和窄屏确认改动；去除展示元素时，也检查没留下空位，以及筛选、媒体标识和键盘操作仍有效。
3. **改动稳定后集中跑回归。** 运行站点测试和受影响的 Linux 视觉用例。失败先确认是产品回归、样本不匹配还是环境问题，再重跑受影响的检查；不因局部改动反复跑全量浏览器套件。先提供可查看的本地结果，单独说明 Linux 是否已完成。

### 10.3 所有改动

至少执行：

```bash
git diff --check
git status --short
```

合并前进行五轴审查：正确性、安全性、回归风险、可维护性、范围控制。发现失败时先定位根因，不放宽关键契约来换取测试变绿。

## 11. 文档规范

- 架构或难以逆转的决定写入 `site/docs/decisions/ADR-*.md`；旧 ADR 不删除，变更时由新 ADR 标记 superseded；
- 阶段事实、PR、验证结果和剩余风险写阶段收口文档；
- 长期反复适用的工作方式写入本规范；
- README 和 `PROJECT_HANDOFF.md` 只保留当前入口、边界和操作方式，并链接详细文档；
- 文档记录原因、取舍、证据边界和重新评估条件，不逐行复述代码；
- 任何数字、SHA、分支和线上状态都视为时间点证据，复用前必须重新核对。

## 12. 完成定义

一次开发任务只有同时满足以下条件才算完成：

- 目标和非目标清楚；
- 改动位于正确边界，没有扩大系统所有权；
- 验收条件通过，失败和未测项被如实记录；
- 差异完成五轴审查；
- 文档与实际行为一致；
- 只提交授权范围内的文件；
- 分支已 push，PR 状态和合并结果得到核对；
- 如声称上线，具有确切主分支、部署和线上证据；
- 临时 worktree 仅在干净且提交可恢复后清理；共享脏工作区保持不动。

## 14. 连续浏览与本机查重的经验补充

- 内容链路验收必须覆盖实际弹窗和页面切换后的推荐节点，不能仅检查独立详情页源码；已看候选耗尽时明确结束，不循环回填来制造停留。
- 本机计数须明确存储范围和失效条件。看到末尾、曝光和点击各自只说明对应事件，不能推断全站留存、满意度或阅读完成。
- SHA-256 证明文件字节相同；感知指纹只筛选人工对照候选。不能用模型或感知相似度自动删除原图；缺少来源字节时必须报告未检查项。
- 异步文件检查和人工确认必须绑定当前文件；保存端重查，旧响应、旧确认和旧版本不能覆盖新选择。
- 发布限制必须覆盖编辑、复制、批量发布、历史恢复、构建和模型语料入口。普通操作不得解除已有 hold，也不得为解除限制而改写原文。
- 临时离线模型隧道只监听回环地址，结束后关闭；向量故障保留最后成功清单，禁止为了通过流程静默降级并覆盖它。
- 功能上线、运行恢复和仓库清理分别验收。结束会话前核对未合并本地文档、远端 heads、活动 worktree、被忽略缓存与私有数据；未执行的清理须明确保留原因。

## 15. 静态性能、依赖与验收经验（2026-11-18）

- 分页须检查初始 HTML、网络请求和无 JavaScript 路径。只隐藏全量卡片不能减少初始下载；目录、卡片和全文索引按实际需求加载，新增卡片重新接入瀑布流和交互观察。搜索才加载的全文索引仍有体积成本，按实测决定进一步分片。
- 图片展示副本与原图分开：按容器宽度选择响应式尺寸，列表动图用静态首帧，详情保留完整动画；验证帧数、时长、循环、EXIF 方向和原图链接。展示封面不能替代原图进入推荐证据。
- 长期 immutable 缓存仅用于字节版本化资源，版本须覆盖模块传递依赖；HTML 和内容目录重验证。构建样本节省多少字节不能直接代表生产提速，发布后核对真实响应与访问性能。
- 依赖升级同时检查锁文件、传递依赖、现存 overrides、Node engines、固定构建版本与平台构建。上游已修复时移除过时覆盖，通过干净安装、审计、正文／图片和部署 dry-run 验证；不强制自动升级。0 项已知告警只说明当前审计结果。
- 逐项检查 CI 日志的直接通过、重试通过和条件跳过，不能把绿色状态报告成全部一次通过。未解释的视觉差异列入待办，保留旧基线；不扩大阈值制造通过。冷加载性能与预热后的固定视觉比较分别验证。
- Playwright 使用精确版本；升级时一次更新站点依赖及锁文件、GitHub Actions 和本地 Linux 容器脚本中的镜像版本，由合同测试防止漏改。
- 滚动测试须等待动作结束，或对测试定位显式使用 instant；任意两帧不能保证 CSS 平滑滚动结束。异步目录加载、浏览器滚动锚点和真实用户滚动分别处理，不能用临时位置覆盖历史位置。测试预览必须由 Playwright 管理前台进程，遇到端口占用更换隔离端口，不复用未知服务或关闭用户预览。
- 会话结束与生产收尾是两个节点。允许结束会话时，须保存准确的未合并 PR、检查所对应的提交、待办、恢复备份和继续入口；待发布分支／worktree 保留。先前主目录中的私有资料不能为了 Git 干净而公开或丢弃。用户另行安排发布时，不合并会触发生产部署的主线。

阶段事实、例外与发布前待办见[性能阶段收尾](PERFORMANCE_CLOSEOUT_2026-11-17.md)；静态分片和媒体缓存取舍见 [ADR-029](decisions/ADR-029-static-catalog-shards.md)、[ADR-030](decisions/ADR-030-image-loading-and-static-asset-caching.md)。
