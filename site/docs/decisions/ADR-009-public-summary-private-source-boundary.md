# ADR-009：外部文章公开摘要与私有来源正文分离

## 状态

已接受

## 日期

2026-07-23

## 背景

本地发布台从 flomo 导入的部分资料来自外部站点。编辑工作需要保留完整原文以便整理、查重和复核，但公开站点定位是“文章摘要”，不应把第三方全文随 Astro 构建部署到公开仓库和 Cloudflare。

SQLite 只是可重建索引，不能成为原文的唯一权威源；公开 Git 仓库也不能承担私密草稿或第三方全文备份。

## 决策

- `publication` 和 `editorial` 类型文章公开发布时，Markdown 正文固定为“不转载全文”的说明；标题、摘要、来源名称、来源链接和公开编辑手记继续进入公开站点。
- 完整来源正文保存在 `workflow/private-sources/articles/<contentId>.md`，该目录被公开仓库忽略。
- 本地管理端读取文章时优先返回私有来源正文，因此公开/私有分离不会降低本机编辑能力。
- 外部文章退回草稿时，正文从私有来源库恢复；再次发布时重新收敛为公开说明。
- `workflow/backups/content-history.git` 的白名单包含私有来源库。SQLite 损坏或删除不影响正文恢复。
- 公开同步前的内容体检会阻止仍含外部全文的非草稿文章。
- 文章和图片标签只能使用仓库内的规范词表；AI 建议、批量导入、手工发布和一次性迁移都经过相同归一化。

## 迁移

运行：

```bash
cd workflow
npm run content:governance:migrate
```

迁移命令是幂等的，会归档来源正文、收敛公开正文、归并标签，并把预先列入复核清单的文章保留为草稿。迁移后必须执行 `npm run content:audit` 和完整站点构建。

## 后果

- 公开仓库和生产站点不再新增第三方全文；
- 本地私有来源目录成为内容安全备份的一部分，必须配置异机私有远程或加密外部备份；
- 相同的公开说明不会参与正文重复检测；
- 若私有来源文件丢失，公开摘要仍可构建，但无法在本地恢复完整导入正文；
- 现有公开 Git 历史不在本次迁移中重写。
