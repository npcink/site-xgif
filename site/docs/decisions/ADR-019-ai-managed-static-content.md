# ADR-019：移除可视化发布后台，由 AI 管理静态内容

## 状态

已采纳，2026-11-12 用户同意实施。取代 ADR-018 中“继续维护本地发布台”的决定；保留 Markdown、Git、私有恢复和静态部署的边界。

## 背景

使用者明确希望后续只使用前端，内容数据交由 AI 管理。现有 Astro 已配置 `output: "static"`，构建时读取 Markdown，线上不依赖发布台。旧 `workflow/server.js` 同时承担 UI API、AI 编辑、上传、索引和发布；继续维护界面与服务已不符合当前使用方式。

直接删除整个 `workflow/` 会连同 R2 台账、私有正文、备份、回收站和发布规则一起丢失。仅隐藏界面又会继续承担服务、安全会话和浏览器测试的维护成本。

## 决策

- 移除管理 HTML/CSS/JS、HTTP 服务、服务启动器、旧界面 AI 作业/隧道和仅供管理服务使用的状态适配代码及测试。
- AI 直接编辑既有 Markdown；Astro Schema、内容检查、稳定 ID、来源与公开范围约束继续生效。
- 保留本机按需执行的内容检查、段落与历史迁移、SQLite 恢复、私有 Git 备份、R2 对账与清理、离线推荐工具。
- 为原来只能从 HTTP 服务使用的图片检查/上传和隔离内容同步增加薄命令行入口，复用既有模块，不新建编辑器、API 或内容数据库。
- 图片操作与内容同步默认只检查，显式执行才上传或推送。内容同步逐文件检查，只同步 `ready` 的公开内容及引用图片，以哈希阻止检查后的变更，保留可恢复回执。
- GitHub PR 不自动合并，Cloudflare 继续只部署 `site/dist`。线上核验仍独立于提交、推送和构建状态。
- 原有私有目录和台账原位保留；本次代码迁移不改写或迁移真实内容。

## 替代方案

继续维护旧后台无法减少维护面；引入在线 CMS 会增加运行服务、认证和第二套数据管理；完全删除所有工具会丢失确定性检查和恢复能力。选择静态前端加按需工具，保持最小运行系统。

## 后果

网站和工具 CI 独立；前端测试不再读取发布服务源码，工具不再依赖 Playwright。主分支目前要求 `Local publisher` 检查，保留其名称作为兼容检查，但只执行 CLI 测试，不调整远端保护规则。

AI 负责文件操作，不因此获得虚构来源、授权、完整性确认、自动合并或声称上线的权限。取消后台也取消其浏览器暂存、表单和任务队列；未保存的浏览器输入应在停用前导出。旧运行文件不清理。SQLite 只作为按需维护的派生索引和推荐缓存，网站运行与日常编辑无须启动它。

## 迁移、验证与回退

迁移在独立 worktree 从 `origin/main` 实施，保留主工作区未提交内容和所有被忽略私有数据。验收为工具测试、真实前端构建与站点测试通过，命令行默认检查不触发外部写入，前端不引用管理服务。

回退可通过 revert 本次代码提交并恢复旧依赖；已有 Markdown、URL、R2 对象、私有备份和回执保持原位，不能为恢复旧界面覆盖新内容。当前操作方式见 [内容工具](../../../workflow/README.md)。
