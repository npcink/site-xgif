# ADR-012：离线混合推荐与静态结果清单

## 状态

已接受

## 日期

2026-07-24

## 背景

文章与图片已经使用统一内容 ID 和静态详情页。仅按共享标签排序时，标签较宽泛或图片标签较少会产生弱相关结果；但为一个单人维护的静态站点增加线上向量数据库、运行时 AI 接口或用户画像，会破坏现有的简单性、隐私和可恢复边界。

关键约束：

- Markdown 和图片元数据继续是内容权威源，推荐流程不得修改或删除正文；
- 草稿、`public: false` 内容和当前页面自身不得进入推荐候选；
- Astro 构建和线上页面不能依赖 M4、Ollama、SQLite 或外部 AI 服务；
- M4 Ollama 继续只监听回环地址，从 M5 通过临时 SSH 隧道访问；
- 本地模型、向量和密钥不得进入公开 Git 或 Cloudflare 产物；
- 模型不可用时仍要有稳定、可解释的推荐结果。

## 决策

采用“规则召回与兜底 + 本地向量重排 + 静态 ID 清单”的离线混合架构。

第一层使用确定性规则评分：

- 共享标签按标签稀有度加权，避免宽泛标签支配结果；
- 标题、摘要、分类、标签、图片情绪和使用场景使用中文二元词与英文词元计算文本相似度；
- 新鲜度只占较小权重；
- 文章推荐默认选择两个相关内容，再加入一个由内容 ID 稳定决定的探索内容。

第二层使用本地 OpenAI 兼容 Embeddings 接口。默认模型为 `qwen3-embedding:0.6b`，在 M4 Ollama 运行。混合分数为：

```text
0.55 × 向量相似度 + 0.35 × 规则相关度 + 0.10 × 新鲜度
```

向量输入由内容类型、标题、摘要、标签、分类、情绪、场景和受限长度的正文组成。输入哈希、模型名称、向量维度和向量保存在 `workflow/.runtime/xgif.sqlite3`；内容哈希未变化时复用缓存。缓存损坏或删除后可以从公开 Markdown 和指定模型重新生成。

生成器把最终结果写入 `site/src/data/recommendations.json`。该文件只包含：

- schema 版本；
- 生成时间和公开语料哈希；
- `rules` 或 `hybrid` 模式；
- 模型名称与向量维度；
- 每个公开内容对应的推荐内容 ID。

Astro 页面把清单作为优先顺序，再用站内规则实时校验和补足。因此，清单过期、缺少某个内容 ID 或向量服务不可用都不会阻断构建，也不会展示草稿或已删除内容。

本地接口响应按不可信输入处理：必须校验 HTTP 状态、JSON 结构、批次数量、索引、有限数值和一致维度。向量端点未配置、超时或响应异常时，默认回退到规则清单；`--require-embeddings` 仅用于严格验收。

## 备选方案

### 只按标签推荐

实现最小，但当前标签密度不均，跨文章与图片的召回较弱。保留为兜底，不作为唯一排序依据。

### 在线向量数据库和运行时检索

可以即时更新，但会增加在线服务、认证、费用、隐私和故障面。当前内容规模和更新频率不需要这套复杂度，因此拒绝。

### 让生成式大模型直接输出推荐

容易得到表面合理但不可复现的结果，也更难校验遗漏、草稿泄漏和内容 ID 幻觉。向量只负责相似度，候选过滤和最终清单仍由确定性代码控制。

### 把向量提交到公开仓库

能减少本机重算，但会增加仓库体积并把可重建模型产物变成长期公开资产。只提交小型 ID 清单，向量留在本机缓存。

## 后果

- 线上仍是纯静态站点，不新增数据库和运行时 AI；
- 首次生成需要本地模型和临时隧道，之后只对变更内容增量计算；
- 更换模型名称会自然形成独立缓存，必须重新生成清单并人工抽查推荐质量；
- 模型离线时仍可更新和构建站点，但生成清单会明确标记为 `rules`；
- 推荐质量需要用真实内容持续抽查，权重是可测试的产品参数，不是永久真理。
