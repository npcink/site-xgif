# ADR-031：草稿入库与生产展示分开

状态：已接受。日期：2026-11-25。部分更新 [ADR-013](ADR-013-public-code-private-content-github-boundary.md)，仅改变可公开阅读的草稿的入库规则。

## 决策

- 允许在公开 GitHub 上阅读且已核对来源、授权和隐私的未上线内容，可按文件单独提交。文章和图片保留 `draft: true`；未上线图片同时保留 `public: false`。已有 `publicationHold` 不解除。私密草稿、私有来源、完整台账、凭据和运行数据仍不进入公开仓库。
- 入库不等于上线。草稿不生成生产详情或预览路由，也不出现在列表、搜索、推荐、RSS、站点地图和收藏目录。生产构建回归检查核对非公开内容 ID 不出现在这些产物中。
- 草稿标记不能保护静态文件。`site/public/` 会被直接部署，公开 R2 对象也可直接访问；两处都不存放未上线专用素材。只需在 Git 中版本化的附件应放在生产构建不读取的目录，不能由公开页面引用。
- `content:sync` 仍只处理符合上线条件的内容。草稿版本使用独立 Git 提交；合并会触发生产构建的分支仍需明确授权。此次规则调整不自动迁移本地草稿，也不改变仓库可见性。
- 历史 `internalNote`、`internalReviewStatus` 等字段未批量迁移；存在于公开 Markdown 的值仍可被读取，页面只使用明确的公开 `editorNote`。新的私密复核材料放入 `workflow/private-sources/`，不能因草稿可公开阅读就将内部材料附在公开文件中。迁移历史字段前，需先保留原值与复核状态并验证发布阻断规则不变。

## 取舍与回退

全部草稿只留在本机或私有历史最保守，但可公开阅读的草稿没有必要因此失去普通 Git 协作。放进公开仓库就意味着可以被阅读和复制；之后删除文件或把仓库改私有，不能撤回已被他人保存的副本。需要收紧时可恢复「只在私有历史保存未上线内容」的规则，但不能把它当作对既有公开记录的清除。
