# ADR-008：公开内容使用不可变稳定 ID

## 状态

已接受

## 日期

2026-07-23

## 背景

文章和图片详情页原先直接使用 Markdown 文件名作为 URL。文件名包含发布日期和中文标题，例如 `/images/2026-07-23-去摧毁金融区吧/`。这种地址可以访问，但复制后会显示很长的百分号编码，并且标题整理或改名会改变公开链接。

公开 URL 已经是读者、搜索引擎和外部分享依赖的接口，不能继续与可编辑标题绑定。当前站点仍是 Astro 静态构建，不需要为稳定 URL 引入 D1、线上 CMS 或额外 Worker 逻辑。

## 决策

- 每条文章和图片使用全局唯一的 `contentId`，格式为 `YYYYMMDD-xxxx`，其中 `xxxx` 是四位小写字母数字。
- 日期部分取创建内容 ID 时的发布日期，仅用于可读性；`contentId` 生成后永久不变。之后修改标题、正文或发布日期都不能改 ID。
- Markdown frontmatter 和文件名使用同一个 `contentId`，例如 `20260723-k7m2.md`。
- 文章与图片详情共用根级 URL，例如 `/20260723-k7m2`；`/articles` 和 `/images` 只保留为分类索引。
- 除网站根目录 `/` 外，所有公开页面 URL 都不带尾斜杠；Astro 和 Cloudflare 静态资源层共同执行这一规范。
- Astro 的文章卡片、图片卡片、详情页、结构化数据、RSS 和 sitemap 只使用 `contentId` 生成公开 URL。
- 静态构建必须检查所有公开文章和图片的 `contentId`；格式错误或跨类型重复时直接失败，避免同一路径指向两项内容。
- 本地发布台自动生成并检查 ID，编辑者不需要填写。
- 当前项目仍在开发且没有访客，现有标题型路径及 `/articles/{contentId}`、`/images/{contentId}` 直接失效，不保留迁移重定向兼容层。

## 备选方案

### 继续使用日期加中文标题

可读性较强，但分享地址过长，标题修改会破坏链接，因此拒绝。

### 只使用顺序数字

地址最短，但容易猜测数量和发布顺序，也需要额外的全局计数权威源，因此拒绝。

### 使用正文哈希

无需随机数，但正文修改会改变哈希；截断哈希仍要处理碰撞，且不利于人工核对，因此拒绝。

### 只新增 `contentId`，保留中文文件名

可以实现稳定 URL，但文件名、frontmatter 与路由会出现三套标识，后台排错更困难。当前内容量小，适合一次性统一，因此拒绝。

## 后果

- 标题可以自由修改，已分享 URL 不变；
- 文章与图片在公开 URL 层使用同一命名空间，任何跨类型 ID 冲突都会阻止构建；
- 当前全部内容需要一次性迁移文件名、frontmatter 和本地台账路径；
- 四位后缀的空间适合当前低频发布，但发布台仍必须扫描全库并处理碰撞；
- 正式对外后，公开 URL 应视为不可破坏的接口；若未来再次迁移，必须先另行评估永久重定向。
