# ADR-030：图片尺寸、动图封面与静态资源缓存

状态：待审核候选，未部署。日期：2026-11-17。

## 原因与决定

列表分片完成后，媒体仍是主要大资源。一张 88 帧动图的 320px 展示副本为 1,342,650 字节，640px 为 4,639,726 字节。图片卡片原先统一声明桌面宽度 40vw，与三列布局不符。

- 图片卡片按首页、图片库／标签、搜索的容器宽度和响应式列数提供 `sizes` 回退。延迟图片使用 `auto` 优先按实际显示槽位选择资源；不支持的浏览器使用显式尺寸。分页新卡片继承当前列表的尺寸约定。
- 动图列表及推荐卡片使用首帧 WebP，点击卡片进入详情／弹窗后加载并播放完整动画。单图文案提示“动图 · 点开播放”。图集缩略图始终使用静态首帧；其他主图仍在选中时才加载。关闭 JavaScript 时卡片进入普通详情页，原图链接可用。
- 首帧是独立转换参数，进入图片缓存哈希以及开发图片端点的编码／解析。原图、完整动画、帧间隔、有限循环、稳定 ID、图集关系和推荐证据不变。首帧封面不是推荐输入。
- 构建完成后，以所有前端脚本及图片比例 CSS 的公开字节生成版本目录 `/static/<hash>/`，将 HTML 的资源引用改到该目录。模块保持相对导入，共用版本包含所有传递依赖，避免入口未变而依赖变更的缓存失效遗漏。原始无版本路径保留短缓存兼容。
- `/static/*` 与 Astro 内容哈希资源 `/_astro/*` 使用一年浏览器缓存及 `immutable`。HTML 和 `/catalog/*` 保留重验证；不承诺按内容快照命名的卡片 HTML 永久不变。

没有新增运行服务、依赖、后台、付费转换或数据存储。缓存策略需部署后再核对真实 HTTP 响应，本地构建通过不代表生产已生效。

## 构建缓存补充（2026-11-18）

GitHub 站点 CI 在 `npm ci` 后恢复 `site/node_modules/.astro/assets`，只保存公开图片的转换副本及其缓存元数据，不保存 Astro 内容存储、草稿、完整 `node_modules` 或私有工具数据。缓存前缀包含平台、架构、依赖锁、Astro 配置、图片服务和展示组件指纹；提交 SHA 区分新快照，并允许同一图片管线复用前一次成功构建。图片及转换参数继续由 Astro 的逐资源缓存键判定，不以 CI 缓存命中替代构建和测试。

该路径沿用 Astro 默认缓存位置；[Cloudflare Workers Builds 文档](https://developers.cloudflare.com/workers/ci-cd/builds/build-caching/)也支持自动识别 `node_modules/.astro`。本次没有修改 Cloudflare 控制台开关，不能据此声称生产构建缓存已启用。删除本地缓存或 CI 缓存只会重新下载和转换，不影响 Markdown 与原图。

本机冷构建后再执行构建，493 个生成图片全部复用缓存，图片转换阶段约 99ms，493 个副本的文件名与 SHA-256 完全一致；整次 Astro 构建约 14.8 秒。该结果仅证明本机热缓存复用和产物一致，不代表跨机器或生产构建提速比例。跨 CI 任务的缓存存取另由后续 Actions 运行记录确认。

## 体积证据与限制

同一样本新静态首帧：320px 为 18,330 字节，640px 为 70,186 字节。320px 相比之前动画副本减少约 98.6%；这来自不在列表播放全部帧，不是声称同样动画质量压缩了 98.6%。用户打开详情仍会下载完整动画。对动画首帧以外的动作理解，仍需进入详情。

1920px、1x 屏幕下，实际卡片槽位约 361px：同一静态样本改前 `40vw` 选择 960px／39,206 字节，改后选择 640px／24,520 字节，减少约 37%。这是一张样本的资源选择结果，不代表所有图片统一减少该比例。

缓存收益主要针对重复访问，首次冷访问仍需下载当前所需资源。所有脚本共用版本意味着修改一个脚本会使整个脚本集合的版本变化；当前总量很小，以简单可靠的依赖失效为先。

## 统计服务选择

用户明确选择免费的 Cloudflare Web Analytics。控制台核对发现现有 `xgif.cn` 记录已启用，使用自动注入并排除欧盟访客的模式；实际正式域名浏览器 DOM 也包含官方 beacon。终端单次抓取 HTML 没有该标签，不足以判定服务未启用。CLI 现有 OAuth 不具备 RUM 管理权限，因此使用已登录控制台进行只读核对。

候选只移除爱站加载器及其 CSP 域名，保留 Cloudflare 所需域名，不新增手工 beacon、不重复安装、不改变线上设置。原爱站当前脚本仍含动态执行与 unload；本次检查的 Cloudflare 官方脚本使用可兼容页面恢复的实现，未发现这两项。不能据此保证所有浏览器始终命中 bfcache，仍须授权发布后核验实际页面与请求。

自动注入由 Cloudflare 管理，`noindex` 不会关闭它；旧文档对爱站的页面排除规则不能直接用于 Cloudflare。隐私说明相应更新，区分浏览器本地搜索／收藏与性能遥测，保留不使用分析 Cookie、URL 查询参数／片段剔除以及当前区域排除的实际边界。现有历史统计不删除，收藏 D1 汇总不变。

## 验证

检查首帧产物仅一帧、详情仍含原动画帧数、循环和时间不变、原图链接不变；桌面、手机和高像素密度的尺寸选择；翻页后卡片尺寸、弹窗打开、CSP、瀑布流、静态资源存在性、模块依赖变更导致 URL 更新，以及 Linux 视觉基线。不得通过放宽阈值掩盖排版变化。

## 本轮验证记录

- 构建及 579 个 HTML 页面的链接检查通过；站点最终 75 项单元／契约测试通过，包含静态封面、动画帧／时长／循环、EXIF 方向、公开资源存在性和依赖缓存失效。部署 dry-run 通过，未执行生产部署。
- Linux 最终全套 128 项通过、2 项专用图集夹具按既有条件跳过，没有更新视觉基线或放宽阈值。图片、动图点击、响应式尺寸、高像素密度、CSP、瀑布流、分页、历史、弹窗和性能用例均覆盖。
- 第一轮媒体专项为 41 项通过、1 项夹具退出时的异步路由错误重试通过；将退出清理与既有 CSP 用例统一为断言后忽略取消中的请求，完整复验无重试失败。
- 上一候选的云端检查暴露手机历史滚动误差约 37–38px。复现确认加载提示使浏览器滚动锚点临时移动，内存位置覆盖了原来位置。现在翻页时冻结来源位置，目录加载期间不记录临时滚动；相关手机分页／布局 20 项复验通过，最终全套也通过。文章截图的可选字体冷缓存差异通过预热后捕捉参考图解决，冷加载 CLS 另有独立检查。
- 本地 Wrangler 静态响应实测：版本脚本及 `/_astro` 样式为 `public, max-age=31536000, immutable`，页面及目录为 `public, max-age=0, must-revalidate`。生产域名是否生效仍须发布后核验。
- 原图、正文、来源、稳定 ID、日期、图集关系和推荐清单没有修改。阶段证据保留于被忽略的 `workflow/.runtime/media-performance-20261117/`，不进入公开 PR。
