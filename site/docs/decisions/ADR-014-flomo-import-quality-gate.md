# ADR-014：Flomo 导入采用单一路径与确定性发布门槛

## 状态

已接受

## 日期

2026-07-25

## 背景

本地发布助手的真实目标是把 Flomo 导出内容快速整理为可发布文章，而不是让用户在“先 AI 整理、再分段、再找内容库、再发布”的多按钮流程中重复判断。

此前出现了三个相互关联的问题：

- 导入页存在职责重叠的 AI 与草稿按钮，无法判断该先点哪一个；
- 长段落只在体检中提示，单篇、批量或导入发布路径可能没有同一条硬性约束；
- 从“内容体检与标签”打开文章时，只带入正文，未带入为什么需要人工处理及处理顺序。

同时，Flomo 原文是用户内容。段落优化不能演变为自动改写，也不能因为修复历史内容而新增一排一次性按钮。

## 决策

1. Flomo 导入保留两种明确结果：主动作“整理并发布所选”，备选“保存为草稿”。不保留独立的批量 AI 整理或“整理段落”按钮。
2. 发布前统一执行质量检查。任一 Markdown 段落超过 180 字即为错误，单篇编辑、批量发布和 Flomo 直发均不能绕过。
3. 主动作仅在长段落时调用既有 AI 整理能力；其输出只能插入 Markdown 段落空行。服务端忽略换行后逐字比对原文，任何删改、改写、合并原有段落或单换行伪分段都会拒绝。
4. AI 不可用、结果不合规、来源/重复等条件未满足时，不自动发布；用户可以保存草稿后再处理。
5. 内容体检保持只读诊断。“打开处理”直接进入编辑器，并以内联提示卡带入该条目的 blocker、warning 与下一步，不把这些诊断写进正文、公开摘要或 `internalNote`。
6. 导入复核仍使用现有的“我已确认”明确确认控件；内容位置使用“草稿 / 本地发布 / 云端流程”归类，Git、部署和验证细节保留在详情中。

## 替代方案

### 新增“AI 整理段落”或“批量修复全部”按钮

被拒绝。它会把一个发布质量要求拆成新的工具入口，用户需要先理解哪个按钮负责正文、哪个负责发布；历史问题越多，按钮越多。现有 AI 动作已经覆盖安全分段，体检入口只需要把问题带到那里。

### 让 AI 直接改写或自动通过长段落

被拒绝。段落优化的目标是可读性，不是编辑作者原文。仅靠提示词无法保证原文完整性，必须由确定性逐字校验和发布门槛共同保证。

### 将体检结果持久化为内部备注

被拒绝。体检结果是对当前文件的可再生成诊断，写入 `internalNote` 会把过期提示变成新的内容状态，并混淆“来源复核”与“自动化检查”。

## 后果

- 用户的最短路径是：Flomo 导入 → 整理并发布；不满足条件时才降级为草稿。
- 历史内容不会被后台自动改写；从体检打开后，用户能在同一编辑页看到原因、使用既有 AI 动作并执行“仅检查”。
- 发布器多了一条全路径质量不变量，任何新发布入口都必须调用 `checkArticleQuality`。
- 前端文案、体检状态与发布校验必须同步更新；只做“建议分段”的审计而不做发布阻断不再可接受。

## 验证

- `workflow/tests/local-http.integration.mjs` 验证超过 180 字的单段正文使 `/api/quality/article` 返回 `ok: false`；
- `workflow/tests/publisher-contract.test.mjs` 约束单一路径、体检直达编辑器和提示卡；
- `workflow/tests/browser/publisher.desktop.spec.mjs` 覆盖导入内容确认与内容库位置筛选；
- 发布前执行 `workflow/npm test`、`workflow/npm run test:browser` 与 `git diff --check`。
