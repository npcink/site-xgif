# ADR-005: 新图片使用 Cloudflare R2 内容寻址存储

## Status

Accepted

## Date

2026-07-23

## Context

XGIF 的公开站点继续由 Workers Static Assets 部署，内容事实来源仍是 Git 中的 Markdown。随着表情包数量增长，把每个新图片字节都提交到 Git 会扩大仓库和构建上传体积，但当前项目没有多人在线编辑、运行时检索或线上管理后台的需求。

本地发布台已经负责图片格式与尺寸校验、SHA-256 查重、来源契约、授权台账和 Git 提交。图片存储的变化不应把这些职责迁移到 Cloudflare，也不应顺带引入 D1、Vectorize 或 Worker API。

## Decision

- 创建 R2 Bucket `xgif-memes-prod`，只保存以后由本地发布台新增的图片字节。
- 使用 `img.xgif.cn` 作为正式公开域名；不使用 `r2.dev` 作为生产地址。
- 对象键固定为 `memes/<sha256>.<ext>`，并设置 `Cache-Control: public, max-age=31536000, immutable`。内容变化必须生成新哈希；同一哈希的重复上传只会写入相同字节。
- 本地发布台先校验和查重，再使用仓库锁定的 Wrangler 上传对象，并通过不带查询参数的正式 URL 验证；只有成功后才写 Markdown 和 Git 台账。
- `workflow/records/r2-assets.jsonl` 是对象位置与哈希台账，Markdown 继续保存标题、描述、来源、授权和发布状态。
- 现有 `site/public/images/memes/` 图片不迁移。R2 未显式启用时，本地目录仍作为安全回退。
- R2 的启用和发布凭据只存在于本机 Cloudflare 登录态，不提交账号令牌、S3 密钥或其他凭据。
- `img.xgif.cn/memes/` 使用一年 Edge TTL；WAF 拦截外站非空 Referer 与所有查询串，避免简单盗链和查询串绕缓存。本域、空 Referer 和本地预览继续可用。
- 对该路径启用单 IP `200 次/10 秒` 的速率限制并排除 Cloudflare 已验证机器人；`$1`、`$5` 预算告警只负责通知，不视为费用硬上限。

## Alternatives Considered

### 所有图片继续提交 Git

当前少量图片完全可行，且最简单；但未来批量表情包会持续放大仓库和每次静态部署的资源集合。保留它作为旧图片和显式关闭 R2 时的回退，而不是新图片的默认长期路径。

### 立即迁移全部已有图片

当前本地自托管图片很少，迁移收益有限，却会改写历史内容 URL 并扩大验证范围。先只处理新图片，等旧资源体量或部署成本形成真实痛点后再单独决策。

### 增加 Worker 上传 API 或线上后台

会引入身份认证、滥用防护、密钥管理和运行时故障边界。当前只有单人本地发布需求，本地 Wrangler 已能完成受控上传，因此拒绝。

### 使用 D1 或 Vectorize 管理图片元数据

现有 Markdown 与 JSONL 台账已经满足构建、查重和追溯。新增数据库会产生双重事实来源；Vectorize 也不能替代精确哈希查重，因此拒绝。

## Consequences

- 新图片字节不再进入 Git 或 Workers Static Assets 构建产物，站点通过 `img.xgif.cn` 读取 R2 对象。
- 发布新图片依赖本机有效的 Wrangler 登录态、R2 Bucket 和自定义域名；任一环节失败时发布器会停止，不生成坏链接。
- 公开图片不支持查询参数；若未来需要图片变体，必须另设受控 URL 契约，而不是用任意查询串绕缓存。
- 空 Referer 仍然允许，以兼容浏览器隐私策略、直接访问和消息应用预览；因此防盗链是成本抑制措施，不是访问授权机制。
- Git 仍然可以审查每次内容和授权变更，但不能单靠克隆仓库恢复 R2 图片字节；R2 的生命周期、备份和删除策略需要另行治理。
- R2 是公开源站，不提供自动格式转换或尺寸优化。若未来确有图片变体需求，应单独评估 Cloudflare Images 或构建期派生，不把它隐式混入本决策。
