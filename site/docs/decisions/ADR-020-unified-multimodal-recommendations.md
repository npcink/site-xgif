# ADR-020：统一使用 Qwen3-VL-Embedding 2B 生成图文推荐

## 状态

已采纳，2026-11-12 用户明确同意统一模型。更新 ADR-012 中的模型、输入与失败恢复规则；保持离线生成、Markdown 权威源和纯静态前端边界。

## 背景

此前 `qwen3-embedding:0.6b` 只编码文章与图片的文字资料，无法直接利用画面。M4 已安装 Qwen3-VL-Embedding 2B，11 张站内图片的小样本验证了中文找图与图片相似度，但不足以证明全站推荐质量。

把图片描述直接拼入图片编码会使文字近似掩盖画面差异；单独切换图片模型又无法与旧文章向量直接比较。因此统一模型，同时保留规则排序和候选过滤。

## 决策

- 使用模型 `RizwanMalik/qwen3-vl-embedding-2b:q8_0-q8_0`，2048 维，通过原生 Ollama `/api/embed` 编码。文本输入为字符串；图片输入为含 base64 画面和空文本的对象。不向旧 OpenAI 文本接口伪装传入图片。
- 文章沿用标题、摘要、标签与前 1600 字符正文；图片只编码画面，文字资料仍影响既有规则分数。评分继续采用 55% 向量相似度、35% 规则相关度、10% 新鲜度。
- 图集所有成员按原顺序串行编码，各向量归一化后平均，形成该内容的向量。GIF / 动态 WebP 目前只分析首帧，不能声称理解完整动作。
- 图片仅来自 `site/public` 内的真实文件，或 R2 台账对应且 SHA-256 一致的本地私有备份；禁止路径越界和任意外链下载。推理副本最长边为 768 像素，原始图片与 Markdown 不改动。
- 缓存按模型名分开，指纹包含 Ollama 模型 digest、输入管线版本、文本资料及有序图片字节哈希；同名模型更新也必须重新生成。不混合旧 1024 维文本向量与新向量。
- 请求验证数量、有限数值、非零向量、一致维度与默认模型的 2048 维；模型必须声明 embedding 和 vision 能力。全语料维度验证通过后才保存新缓存。
- 文章到图片、图片到图片与图片到文章的候选先经过余弦相似度 0.35 门槛。此值是小样本起点，需要后续真实浏览验证，不能解释为匹配概率。文章之间保留已有相关内容和探索机制。
- 静态清单保持 schemaVersion 1，新增可选的 `embedding.provider`、`inputVersion`、`modelDigest`、`selection.imageMinSimilarity` 与每条记录的 `sourceType`。前端对带门槛的图片相关推荐只使用经过筛选的 ID，空数组代表没有合适候选；不回填弱相关内容。缺少记录的新内容或旧清单继续使用既有规则兜底。
- 正常命令受内容工具互斥锁保护。请求、图片或模型失败时，保留现有成功 hybrid 清单并非零退出；严格模式失败不写清单；显式 `--rules-only` 可以覆盖为规则清单。故障事实只保存在本机运行记录。

## 备选方案与后果

只保留文字元数据无法直接利用图片；分别使用两个模型的向量不能直接算余弦；采用线上多模态 API 或向量数据库会增加运行依赖与数据边界。选择同一离线模型和静态 ID 清单，前端和 Cloudflare 均不需要模型、SQLite 或私有图片备份。

首次迁移需要重算公开语料，推荐数量可能减少。内容更新、权重更新、画面门槛与真实推荐体验应独立验证；草稿、非公开及 publicationHold 内容继续排除。

## 验证与回滚

验证原生图片请求、图集非封面字节更新、缓存命中、模型 digest 变化、坏响应、缺失/损坏图片、路径越界、故障保留以及前端尊重空候选。随后用真实公开语料严格生成、增量复跑，检查浏览器推荐与 Linux 视觉基线。推荐内容变化导致的截图差异必须逐项确认。

回滚时恢复此前的代码和静态推荐清单，并将本机 `.env` 改回 `XGIF_EMBEDDING_PROVIDER="openai"`、旧 `/v1` 地址及旧模型。旧向量缓存可保留，不删除或覆盖用户内容、图片、草稿与台账。
