# ADR-011：本地发布安全与生产证据链

- 状态：已接受
- 日期：2026-07-24

## 背景

XGIF 的公开站点是 Cloudflare Workers Static Assets，管理器只在单人电脑的回环地址运行。静态站不需要线上后台，但“仅本机”并不等于浏览器请求天然可信；DNS rebinding、跨站请求、旧进程和本地索引全量扫描都会让日常发布变得不可靠。R2 图片字节也不能只依靠一份远端对象和一行台账。

## 决定

1. 管理器继续只监听 `127.0.0.1`，同时校验 Host、Origin、JSON Content-Type 与每次进程启动生成的 CSRF token。
2. 启动器计算发布器源码版本；健康检查必须返回正确服务标识和当前版本，旧进程自动安全重启。
3. SQLite 仍是可删除重建的本地派生索引，但列表筛选、排序和分页直接使用 SQL；启动后只读取变更过的 Markdown。
4. R2 台账必须同时接受远端 HEAD 与本机私有原始字节校验。孤立对象先连续观察 30 天；删除必须精确确认单个完整对象键，默认命令永不删除。
5. 生产构建生成 `/build.json`，公开构建提交与时间；CI 检查站内断链，定时任务核对真实首页、文章、来源、R2 防盗链和裸域名跳转。
6. 外部文章正文只允许纯文本和 Markdown，不接受导入的原始 HTML。
7. 新上传图片记录已验证的像素宽高，减少页面加载时的布局偏移。
8. 不引入 D1、线上 CMS 或在线管理后台。Markdown、Git、R2 与本机私有备份继续保持现有权威边界。

## 结果

管理器仍然轻量、单人、本地优先，但不再依赖“端口能打开”作为健康证据。SQLite 损坏不会损失内容；R2 对账和删除有独立恢复边界；线上成功可以对应到具体 Git 提交，而不是只看 Cloudflare 控制台的一次绿色状态。

在本决策落地时，裸域名 `xgif.cn` 的 301/308 仍由站点所有者在 Cloudflare 配置。定时生产巡检会在该配置缺失时报警，本地检查只提醒而不阻断。

## 后续状态

2026-07-24，站点所有者已完成 Cloudflare 代理 DNS 和 Single Redirect 配置。HTTP 与 HTTPS 裸域请求均返回 301 到 `https://www.xgif.cn`，路径和查询参数得到保留；`REQUIRE_APEX_REDIRECT=true` 的生产巡检通过。
