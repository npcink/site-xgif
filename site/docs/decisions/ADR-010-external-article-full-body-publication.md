# ADR-010：外部来源文章公开完整正文

## 状态

已接受，替代 [ADR-009](ADR-009-public-summary-private-source-boundary.md)

## 日期

2026-07-24

## 背景

ADR-009 将外部来源文章的完整导入正文留在本机，公开站点只展示编辑摘要和来源入口。站点运营者现决定让已经发布的外部来源文章直接展示完整正文，并通过固定的来源链接、权利说明和反馈邮箱处理后续更正或下架请求。

该决定只改变公开正文边界，不改变草稿、来源核验、内容 ID、SQLite 索引、Git 同步和 Cloudflare 部署流程。

## 决策

- `publication` 和 `editorial` 类型文章发布时，完整正文写入公开 Markdown，并随 Git 和 Cloudflare 一同发布。
- 外部来源文章继续强制要求有效的 `sourceUrl`，公开详情页继续显示来源名称和原始来源入口。
- `/rights/` 继续提供 `1355471563@qq.com` 作为更正、署名和下架反馈邮箱。
- `workflow/private-sources/articles/<contentId>.md` 继续保存完整正文副本，作为本地编辑恢复和私有异地备份的一部分，但不再是唯一正文权威源。
- 导入结果仍默认为草稿；本次迁移只恢复已经公开的 32 篇文章，不改变 9 篇待复核草稿的状态。
- 内容体检阻止仍使用 ADR-009 固定摘要占位的公开文章，防止迁移遗漏。

## 迁移

运行：

```bash
cd workflow
npm run content:governance:migrate
```

迁移会从私有来源库恢复旧摘要占位对应的完整正文，继续保留私有副本，并保持草稿状态不变。迁移后必须执行内容审计、发布器测试、站点测试和 Workers 部署检查。

## 后果

- 公开站点、公开 Git 仓库及其历史将包含外部来源完整正文；
- 删除线上页面不会自动清除已经进入 Git 历史或第三方缓存的正文；
- 来源链接和投诉邮箱是署名与事后处理机制，不代表已经获得转载授权；
- 收到有效投诉后，运营者需要及时更正或下架对应内容并完成云端同步；
- 私有正文备份仍可用于误改恢复，但公开 Markdown 也能独立完成站点构建。
