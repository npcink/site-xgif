### 本轮唯一修复

根因：发布状态只依据当前开发分支的 `git status`、跟踪状态和 upstream 判断。当前分支较旧且工作区很脏，即使工作文件与 `origin/main` 的 blob 完全一致，仍会被判定为待提交或待同步。

修复：批量计算当前工作文件与 `origin/main` 的 Git blob；完全一致的内容直接进入线上核验，不受当前开发分支状态影响。远端引用缺失、Git 输出不完整或哈希无法核对时仍然保守失败，不会把未发布内容误判为已发布。

新增两项回归测试后，完整单元/契约测试从 174 项增加到 176 项并全部通过，HTTP 集成通过。修复重放到最新 `origin/main` 的独立 worktree 后，站点 44 项测试与 163 页链接检查、发布台 176 项测试、HTTP 集成和 19 项浏览器测试全部通过。重启本地服务后使用新的浏览器会话复测：

- 124 项内容、0 项草稿、0 项发布中、124 项已上线；
- 同步入口计数为 0 且隐藏；
- 系统状态为“本地发布环境已就绪”；
- “模型迁徙季”详情显示 Git 已进入 `origin/main`，云端已上线。

旧浏览器页因存在浏览器临时草稿，离开确认阻止了真正重载，仍保留修复前的内存状态。本轮没有清除或覆盖该临时草稿；最终复测使用新的浏览器页完成。

### 后续记录方式

在没有外部用户时，继续由 AI 主动构造开发验收任务；写操作一律使用隔离环境。每条记录至少包括：

| 字段 | 说明 |
| --- | --- |
| 日期与任务 | 实际要完成的内容任务 |
| 任务类型 | 导入、编辑、发布、同步或下架 |
| 多余步骤 | 可以被删除或合并的步骤 |
| 状态问题 | 含糊、错误或无法判断的系统状态 |
| 失败与恢复 | 失败点、恢复动作、是否丢失工作 |
| 绕行方式 | 是否必须绕过系统才能完成 |
| 重复计数 | 同一问题累计出现次数 |
| 风险等级 | 普通摩擦或安全、泄漏、错发、不可恢复风险 |

普通功能问题累计至少 3 次后再进入开发候选；安全、隐私、错误发布、状态事实错误和不可恢复问题首次出现即进入 P0。每轮十次任务完成后最多选择一个问题修复。开发验收只证明工程行为，不代表外部用户需求。
