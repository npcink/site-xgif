# 内容链接格式讨论收口（2026-11-02）

状态：用户已确认保留现有格式；本次收口为文档整理，不涉及内容迁移。

## 最终决议

继续执行 [ADR-008](decisions/ADR-008-stable-content-ids.md)：文章和图片 / 表情包统一使用 `/<contentId>`，例如 `/20260723-k7m2`。ID 格式为 `YYYYMMDD-xxxx`，后缀为四位小写字母或数字，公开 URL 不带尾斜杠。

日期取生成 ID 时使用的发布日期，仅作为可读提示。ID 可以在草稿阶段生成，不要求等到首次公开发布；之后修改标题、正文或发布日期，均不得重新生成 ID。Markdown 文件名与 frontmatter 的 `contentId` 保持一致。两类内容共用唯一 ID 空间，生成时跨库查重，碰撞后重抽。

本次不实施无连字符格式 `/20260723k7m2`，也不新增第二套链接、别名或重定向层。现有格式已经满足需求，继续围绕真实内容发布和使用推进。

## 讨论来源与取舍归纳

来源为 Codex 会话「设计文章表情包链接格式」（`019fc722-af18-7992-8d43-4a8c822beb39`，已完整读取）及本次复核、用户确认和收口请求。以下按议题、取舍和决议整理，作为本次所称“理事会讨论”的归纳；现有材料没有独立理事会会议记录，不记录未经提供的参会人、发言或投票。

| 议题 / 提议 | 取舍依据 | 最终处理 |
| --- | --- | --- |
| 年月日加四位纯数字 | 每日只有 10,000 种组合；现有字母数字后缀有 `36⁴ = 1,679,616` 种组合 | 保留四位小写字母数字，并继续查重与重试 |
| 保留日期与后缀之间的连字符 | 人工核对清楚，已被内容、路由和各消费端统一使用 | 保留 `YYYYMMDD-xxxx` |
| 去掉连字符，缩短一个字符 | 技术上可行，但收益主要是外观；旧建议依赖“尚未分享、可直接迁移”的阶段前提 | 本次不采纳，不能据旧前提废弃现有公开地址 |
| 日期取首次发布日 | 草稿已经可以分配 ID；首次上线再改日期前缀会破坏不可变原则 | 以 ID 生成时使用的发布日期为准，之后不跟随日期变化 |
| 文章、表情包分别使用详情前缀 | 现有统一根级路由已可区分内容类型 | 共用根级详情地址，`/articles`、`/images` 保留分类索引职责 |
| 再做一次 URL 格式迁移 | 已公开地址及收藏、推荐、恢复记录都依赖现有标识 | 没有真实阻塞证据，不迁移 |

## 可复用经验

1. 旧建议必须连同适用前提一起复核。开发初期允许的破坏性调整，不会因为“项目仍在开发”而永久适用。
2. URL 是公开接口。迁移成本取决于消费端和外部依赖，不能仅按“删除一个字符”估算。
3. 不可变 ID 与可编辑日期必须分开。日期前缀用于识别，不承担实时同步发布日期的职责。
4. 随机空间大不代表不会碰撞。唯一性由查重、重试和构建约束共同保证。
5. 发现旧建议与当前事实冲突时，应明确终止旧待办，补充决议依据，避免后续 agent 重复实施。
6. 将长期契约留在 ADR，将阶段证据和讨论留在收口纪要；交接文档只保留简短规则和入口。

## 重新评估条件

只有出现真实链接使用障碍、后缀空间导致持续分配失败，或明确的产品需求要求改变公开地址时，才重新评估。届时应另写 ADR，盘点公开 URL、收藏格式、推荐清单、台账和恢复记录，给出映射、永久重定向、回退与验证方案。不得直接运行历史迁移器或重新生成已公开的 ID。
