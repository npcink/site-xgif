# 图片图集发布

日期：2026-11-03

目标：一次选择、追加或拖入多张图片，以一条内容发布；标题、描述、标签、来源和发布状态共用，图片数量为 1–12 张（含封面）。旧单图内容继续兼容；保留原图片编辑时不追溯套用新的上传尺寸与大小限制。

## 使用

在「新建 → 图片」添加图片。缩略图支持预览、移除、拖动排序、前移/后移和设为封面；首张总是封面。每张分别上传，失败后可单独重试，只有全部上传成功才允许保存内容。现有 JPEG、PNG、WebP、GIF 的格式、大小和尺寸校验仍然适用。

上传成功的图片顺序随浏览器临时资料暂存。尚未上传完成的文件仅保留在当前页面，刷新后需重新选择；界面会明确提示。选择文件会保存图片资源，点击「保存草稿」或「发布」才写入内容 Markdown，之后仍需通过原有同步上线流程。

前台列表展示封面和总张数。详情页与详情弹窗支持上一张/下一张、缩略图、方向键/Home/End 和手机横向滑动；原图链接始终对应当前图片。来源声明与投诉入口覆盖整条图集，使用者应确认同一来源信息适用于全部图片。AI 按钮明确只识别当前预览图片，生成结果仍共用于这条图集。

## 内容和接口约定

- `images` 为有序对象数组，每项包含 `src`，可含 `width`、`height`、`altText`；以单行 JSON 写入 frontmatter，沿用现有 Markdown 解析约定。
- `image`、`width`、`height` 和 `ratio` 继续保存首张封面信息，供卡片、推荐和旧内容读取代码使用。
- 无 `images` 字段的旧内容按单图读取，不做批量迁移。
- `POST /api/assets/upload` 增加 `purpose: "image-gallery"`：逐张保存资源，返回 `url`、尺寸和 SHA-256；本地写入 `images/memes/`，R2 保存台账和私有字节备份。
- `POST /api/quality/image`、`POST /api/publish/image` 和图片 `/api/content/update` 接受 `images`；服务端重新核验资源字节、数量、重复图片和尺寸。新图仅接受已保存的本地资源或有台账及备份的 R2 图片，不请求任意远程 URL。
- 图集质量检查返回 `perImage` 的候选和 SHA-256。人工复核通过后保存请求携带 `similarityReviewedHashes`；最终保存重新比对。编辑继续携带 `expectedContentSha256`，拒绝旧版本覆盖。
- 新上传但尚未用于内容的资源不算已发布重复图；查重按已有内容引用计算。已保存图集中的非封面图也进入查重。
- 同步依赖、内容版本哈希、资源库、内容体检和 R2 对账覆盖全部图集成员。移除图片只解除引用，不立即删除共享字节；R2 延用原有孤儿观察期机制。

## 验证入口

- `cd workflow && npm test`：单元测试和真实 HTTP 流程，包含 12 张保存、13 张拒绝、重复/非受控地址拒绝、重开编辑、封面顺序、版本冲突和非封面查重。
- `cd workflow && npm run test:browser`：选择、追加、上限、封面、键盘排序、浏览器恢复、失败重试及发布复核。
- `cd site && npm test`：类型检查、构建、站点契约和链接。
- `cd site && npm run test:gallery`：自动创建并清理临时图集，独立端口 14322，验证桌面/手机独立详情和动态弹窗，包含切图后的可视位置断言，避免图片存在却已滚出视野。

验证只证明本地代码和测试结果。生产 R2 上传、Linux 截图基线和线上部署应分别核验，不能由本地测试推断。
