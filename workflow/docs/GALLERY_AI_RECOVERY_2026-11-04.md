# 图集 AI：有限恢复与识别质量对照

## 本轮结果

在前次[图集验收](GALLERY_ACCEPTANCE_2026-11-04.md)基础上，补齐临时故障恢复、请求诊断、提示词版本升级和真实图片对照。本轮只读取已有公开图片的本机字节备份，调用现有 M4 服务；没有写入用户内容、上传新图片或执行内容上线。

## 故障如何处理

- 每个逐图识别或整套汇总请求最多尝试两次，即自动重试一次。
- 连接失败、超时、429 和 5xx 可以重试；400、401、403、404、格式错误和缺少必填资料不自动重试。
- 默认等待 1 秒。遵守服务返回的 `Retry-After` 秒数或日期；需要等待超过 30 秒时暂停，避免提前重试或长期占住队列。
- 一张图片遇到持续服务故障后暂停剩余队列。汇总失败只重试汇总，保留所有已完成的逐图结果。
- 自动重试期间展示所处阶段、次数和结果保留提示；最终仍失败时可手动重试或填写资料。

每个任务在本机私有运行目录保存最近 64 次请求诊断：请求 ID、识别或汇总阶段、图片索引、尝试次数、开始时间、耗时、HTTP 状态、错误类型及有效的上游请求 ID。模型、权重版本和提示词版本由任务记录关联。HTTP 200 但输出不合格也标为失败。请求 ID 通过 `X-Request-ID` 发给 M4，便于结合时间与模型查询服务日志。

诊断不保存请求头、密钥、原始错误响应或图片数据。界面“识别详情”按需展示最近异常。此次改动提供了后续定位条件，不代表已根治之前真实出现的 M4 500。

## 描述与警告如何处理

提示词升级为 `gallery-v2`，逐图识别与整套汇总使用各自的输出结构：

- 描述以可见内容为依据，饮品、材料、身份和因果关系使用保守表达。
- 明确必填字段及 JSON 结构，缺少字段时阻止采用结果。
- 警告针对具体疑点与检查动作；不对既有警告做静默过滤。
- 汇总输入带图片序号与总数，要求按顺序覆盖整套内容，减少只复述封面的问题。

旧任务与旧建议保留。新版提示词不复用旧版识别缓存；从旧任务点击继续整理时生成可对照的新建议。人工标题、描述和逐图说明保持字段保护，需选择后采用新建议。模型或权重版本升级沿用同一机制。

## 实际对照

同一个 M4 模型 `npcink-vision:qwen35-4b-instruct-16k-v1`，取已有公开内容中的 6 张图片，固定组成 3 套两图图集：文字反应图与水果、像素画与信息图、聚餐照片与动漫表情。两轮使用相同图片字节，各执行 6 次识别与 3 次汇总。

| 项目 | gallery-v1 | 最终 gallery-v2 |
| --- | --- | --- |
| 必填资料生成 | 6/6 图片、3/3 汇总成功 | 6/6 图片、3/3 汇总成功 |
| 汇总覆盖图片数（人工对照） | 5/6，一套遗漏第二张 | 6/6 |
| “文字清晰，无需提出疑问”式肯定警告 | 1 次 | 0 次 |
| 逐图警告总数 | 12 条 | 0 条；数量减少不等于疑点全部解决 |
| 混合主题判断（人工对照） | 正确 2/3 套 | 正确 2/3 套；仍有一套漏报 |
| 聚餐杯中饮品 | 使用“疑似啤酒”并给出多条警告 | 用“黄色液体”描述 |

迭代中曾出现新版提示词省略 description，以及汇总仍遗漏图片。前者通过明确完整结构修正，后者通过独立汇总提示词与带序号的输入修正；失败版本的本机证据一并保留。以上是小样本单轮对照，不构成整体准确率承诺。混合主题、文字、人物动作和语义仍由人工最终复核。

另行对真实 M4 调用注入一次汇总 HTTP 500：两张图片均完成识别，汇总首次失败，等待后第二次真实请求成功。诊断共四条（两次识别、失败汇总、成功汇总），没有重新识别图片。500 为本机注入，不冒充真实上游故障。
