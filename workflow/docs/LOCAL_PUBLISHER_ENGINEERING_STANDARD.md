# XGIF 内容工具工程规范

状态：当前有效；最后更新：2026-11-24。旧发布台界面与 API 规范由 [ADR-019](../../site/docs/decisions/ADR-019-ai-managed-static-content.md) 取代。

## 范围

`workflow/` 只保留 AI 可按需调用的命令行工具和共享规则；不得恢复管理界面、常驻 HTTP 服务、内置 AI 编辑器或第二份正文数据库。AI 在内容文件上工作，工具负责可验证的检查、版本、资源与恢复。

## 数据边界

Markdown 是正文和元数据依据，`contentId` 不可重建。R2 或公开资源目录保存图片字节。SQLite 和感知缓存是可重建派生数据，仅按需使用。私有正文、图片字节备份、回收站、`.env`、SQLite 和发布回执保留本机私有；不部署、不放入公开 Git。

## 文件与发布

- 先读取再修改，精确检查差异，保留其他任务的变更；改写或删除前及批次结束后创建私有快照。
- 内容检查、来源和授权、完整性确认、内部复核、稳定 ID 与已有 hold 均不因换成 AI 操作而放宽。
- 自动整理段落只允许增加空行，不改写原文；短文不靠扩写通过门槛。
- 命令默认检查，外部写入需显式参数；新同步/上传入口共用独占工具锁，旧维护脚本和外部文件操作也应顺序执行。
- 发布只复制选中公开 Markdown 及引用图片，从最新 `origin/main` 隔离建分支并校验文件哈希，不能夹带开发提交或私有数据。
- 推送前保留 prepared 回执，终态持久化后才清理分支；失败沿用原批次恢复，不发布当前开发分支。
- 创建 PR 不自动合并；远端失败保留已推送事实、原分支和下一步。PR、构建与真实线上版本分别核验。
- 图片以 SHA-256 内容寻址，原始字节先私有备份；感知查重仅提供人工候选，不自动删除。图片授权不能由 AI 推测。
- 下架使用版本化文件删除并核对线上消失，不删除 R2 字节来代替内容下架。R2 清理维持 30 天观察、单对象完整键、远端和私有备份检查。

## 批量图片发布

1. **先区分内容和代码。** 只新增符合现有契约的图片时，复用已验收样片，不重跑超分、不重复请求同一范围的确认。按批核对授权与单项 hold、尺寸、动画属性、R2 回读 SHA-256、选中文件及对应的推荐清单快照。放大衍生图沿用 `upscale`，不作为推荐或系列语义证据。
2. **按变更范围验证。** 涉及 Schema、页面或推荐逻辑时，先明确额外验证。公开范围、选中文件和快照已核对且针对性检查通过后，可让草稿 PR 的远端检查与剩余本地验证并行。草稿 PR 也公开；不得夹带未确认素材。合并前核对最终 head、必需检查和授权。
3. **推送失败先核对远端。** 保留隔离提交和私有回执，检查精确分支及已有 PR，再恢复同一批次。确需通过 GitHub API 恢复分支时，核对仓库、主线基准、目标分支、文件树和 PR head，不要直写 `main` 或绕过合并门槛。
4. **分别验收合并和上线。** 先等生产 `/build.json` 命中预期提交，再核对目录、详情页、动图分类和 R2 对象哈希，并运行生产巡检。逐项结果和完整回执只留在私有记录。

时间与发布案例见 [PR #108 放大图发布复盘](IMAGE_UPSCALE_PUBLICATION_RETROSPECTIVE_2026-11-24.md)。

### 组图候选复核

- **另做同批新图复核。** 现有 M4 Ollama 系列向量逐张查询已公开图库，首轮没有让两张待发布的洛必达图互比；无命中不是批内无关联。批次收尾单独按目录和主题并排看原图。M4 可用于批内视觉候选；操作端本机 OCR 可补关键词、台词和水印，两者互补。目录和水印不是出处或授权证据；未授权时设 `XGIF_SERIES_THEME=off`，不用外部视觉服务处理待发布图。
- **跟进搁置候选。** 在私有记录保存候选成员、依据、搁置原因和复核条件。相关单图获准后重新提出成员、顺序和封面供确认，单图公开不替代组图确认。优先用合集页引用既有单图，保留 ID、原链接、原图、署名和回退点，不自动合并。
- **PR #110 的两个漏项。** 游戏两张已经列为同角色候选，出处待核时搁置，单图获准后没有跟进；洛必达两张没有成为初筛候选，后来用 macOS Vision OCR 读取共同关键词和水印，再并排确认同梗的铺垫和反转。补批内候选发现和补跟进是两件事。

## 验证

工具变更运行 `cd workflow && npm test`；涉及站点内容和契约时同时运行 `cd site && npm test`，再 `git diff --check`。外部写入的新入口应覆盖默认检查无外部写入、非法或草稿内容被拒绝、哈希变化与失败恢复。测试使用隔离目录，不操作真实 R2 或生产内容。

合并前按正确性、可维护性、边界、安全和回归风险审查。架构变更写 ADR，README 保持当前操作方式。旧阶段文档作为历史保留，不继续维护已删除界面的交互契约。

## 2026-11-16 收尾规则

- 原文/原图是推荐依据；AI 标题、摘要、分类、描述、alt、情绪和场景只作展示，不能循环变成推荐证据。只改这些字段时先核对清单，不能无条件重算向量。
- 每次发布以最新公开主线加本批文件构造快照，核验清单的源哈希、公开 ID、分组、日期和图片身份；本地全库清单不能直接用于局部发布。
- 图片系列无论置信度多高都只形成候选；追加或合并到已有图集须有具体人工确认，并保留原顺序、来源、ID、旧链接与回退点。
- AI 元数据重跑先冻结模型/版本、提示词、来源、图像帧和预算，小样本通过后再扩展；用户无需逐条编辑，助手负责核验整体和少数例外。工具不得修改原文、授权、来源和公开状态。
- 阶段完成分别核对：源码提交合并、线上版本、私有恢复备份、文档/评测、分支/worktree；不能以一次测试或 HTTP 200 代替整体收尾。
- 私有草稿、完整运行台账和来源备份不是待提交代码；保留在本机和私有历史，不能为了让 Git 状态变空而公开。
