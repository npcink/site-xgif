# 批量发布故障复盘与收尾（2026-07-30）

## 结论

这次出现的 11 条批量发布失败，不是简单的“导入时 AI 没处理好”，也不应由使用者逐篇修复。

真正的问题是导入、质量检查和发布三个阶段此前没有形成闭环：

- 导入阶段负责保留原文和待复核事实，但无法替人确认推荐分组；
- 质量检查发现长段落、内部复核备注和推荐分组缺失，却只返回错误；
- 批量发布复用了通用状态切换，不能在同一工作台内完成可自动修复项和必要人工判断。

因此，系统把本来可以批量解决的问题暴露成了 11 个逐篇任务。修复后的原则是：机器负责确定性整理和校验，人只处理语义判断，并且这些判断应集中在一次批量复核中完成。

## 根因分析

### 1. 导入质量门禁只有发现问题，没有完成问题

导入时保留内部复核备注是正确的安全选择。错误在于后续批量发布只能告诉用户“尚未确认”，却没有提供一次集中确认的工作面。

推荐分组同样属于发布前必须明确的语义字段。它不能由 AI 猜测，但也不应迫使用户逐篇打开编辑器。

### 2. 可自动修复项和人工判断项没有分层

长段落属于可确定性处理的问题：系统可以优先使用本地规则插入 Markdown 段落空行，只有规则无法完成时才调用 AI，并在写入前证明除换行外字符完全未变。

内部复核和推荐分组属于人工判断。旧流程把两类问题都表现成“发布失败”，导致使用者无法区分系统责任和人工责任。

### 3. 批量发布曾被当成普通状态切换

“草稿 → 本地发布”不是一个布尔字段修改。它包含质量体检、正文整理、复核确认、语义字段确认、版本冲突检查和逐项写入。通用批量状态接口不能安全承载这些步骤。

### 4. 源 Markdown 与线上可见文本混为一谈

第二批内容同步后，线上页面已经正确显示，但核验器仍报告失败。原因是核验锚点直接来自 Markdown 源文，包含链接目的地址；这些地址不会作为正文显示在渲染后的 HTML 中。

线上核验必须基于读者真正可见的文本：保留 Markdown 链接标签，去除链接和图片目的地址，再做规范化与锚点匹配。HTTP 200、构建成功或源文件包含某段文本都不能替代这一步。

## 已实施的修复

### 批量发布入口

批量“发布到本地”现在使用专用的检查与执行流程：

1. 服务端读取明确的文件清单；
2. 对每项计算内容 SHA-256；
3. 展示长段落、内部备注、来源、正文和推荐分组；
4. 用户在一个清单内完成复核确认和逐篇分组；
5. 提交时携带每项检查时的 SHA-256 和人工分组；
6. 服务端重新验证版本与分组，再逐项发布；
7. 单项失败保持草稿和选中，其余项目继续；
8. 返回成功、失败、跳过和已处理项目数量。

通用批量状态接口不再允许绕过该流程直接发布。

### 段落整理

- 优先使用本地确定性规则；
- 本地规则无法满足 180 字门禁时才请求 AI；
- AI 结果只允许增加换行；
- 发布边界再次执行字符级完整性校验；
- 任何删除、改写或重排都阻断该项，不影响同批其他内容。

### 人工复核

- 内部复核备注集中在一次批量确认中展示；
- 推荐分组在同一清单逐篇选择；
- 已有分组作为默认值展示，但仍随本次内容版本提交；
- 服务端不信任浏览器传值，使用允许值规范化并重新执行发布前质量检查。

### 同步和线上核验

- 公开内容从最新 `origin/main` 创建隔离 `content-sync/*` 分支；
- 只提交所选内容文件，避免夹带脏工作区中的代码、草稿或记录；
- PR、CI、合并、Workers 部署与线上正文核验分别记录；
- 线上正文锚点使用 Markdown 可见文本，不再把链接目的地址当成读者可见内容。

## 固化后的开发思路

### 系统责任与人工责任分开

| 问题 | 责任方 | 处理方式 |
| --- | --- | --- |
| 长段落、格式规范 | 系统 | 本地规则优先，AI 兜底，确定性校验 |
| 内容版本冲突 | 系统 | SHA-256 乐观锁，拒绝覆盖 |
| 内部备注是否已复核 | 人 | 批量清单一次明确确认 |
| 推荐分组 | 人 | 同一清单逐篇选择 |
| 单项内容质量失败 | 系统 | 只阻断该项并保留选择 |
| 是否真实上线 | 系统读取事实 | 合并、部署、线上内容分别核验 |

### 在问题发生的最近边界修复

- 导入不应擅自作发布决定；
- 发布前门禁不应只报错而不给闭环入口；
- 同步不应修正文内容；
- 线上核验不应使用源格式中不可见的字符。

把修复放在拥有该事实和动作的边界，可以避免同类问题在单篇发布、批量发布或历史内容中反复出现。

### 一次操作完成一个真实任务

如果用户的目标是“把选中的内容发布到本地”，系统应在一个批量工作面中完成所有可批量完成的准备。只有确实需要阅读上下文才能决定的异常，才退回单篇处理。

## 防复发检查清单

- [ ] 导入产生的每一种待处理状态都有明确的后续入口；
- [ ] 可确定性修复的问题不会要求用户逐篇操作；
- [ ] AI 输出在写入边界有结构或不变量校验；
- [ ] 人工语义决定不会被 AI 或默认值偷偷替代；
- [ ] 批量提交携带检查时内容版本；
- [ ] 服务端重新验证浏览器提交的字段；
- [ ] 单项失败不终止整批，失败项保持可重试；
- [ ] 公开内容同步使用最新 `origin/main` 的隔离工作树；
- [ ] CI、部署和线上内容核验分别报告；
- [ ] Markdown 线上核验只使用渲染后可见文本；
- [ ] 新回归测试覆盖用户实际经过的完整交互顺序。
